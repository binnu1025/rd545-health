# 下一次實機測試方案（尚未執行）

## 本輪完成

離線實驗性 decoder 支援分段順序、16-bit 位移、零補齊、長度與 checksum 檢查。只接受已觀察到的 346-byte b010 格式及五個固定位置 tag；其他格式明確拒絕，不搜尋任意 tag 猜值。不輸出未確認部位數據。

合成測試涵蓋長訊息、損毀 checksum、錯誤命令／長度／tag、缺段、重複與 padding。另在私人擷取檔執行相同 TypeScript 模組，五個結果與私人截圖參考全部相符。未增加主動 BLE 命令；單樣本不足以認定正式支援。

## 官方 App 流程的證據與推測

| 階段 | 觀察 | 不確定之處 |
|---|---|---|
| 通知 | 寫 descriptor 0x0011 並讀回 | handle 與 UUID 尚無同次 discovery 證據 |
| 0003 → 8003 | TX 含 App 識別字串 | 疑似身分協商；不能直接使用別人的識別字串 |
| 0010 → 8010 | 每次內容改變，有時間樣式欄位 | 疑似時間設定，非確定只讀命令 |
| 0020 → 8020 | RX 含 RD-545AS | 設備資訊候選，副作用未獨立確認 |
| 1000 → 9000 | RX 含個人資料樣式欄位 | 疑似讀取 profile，範圍與選擇方式未知 |
| 1002 → 9002 | TX/RX 含 profile 樣式資料 | 有修改個人設定風險，不重播 |
| 2010 → a010 | 第二次等待約 64 秒 | 啟動／等待量測候選，需受控測試 |
| 3000 → b000 | 完成後短交換 | 用途未知 |
| 3010 → b010 | 收到與畫面相符的結果 | 取得結果候選，是否消耗／刪除紀錄未知 |
| 0001 → 8001 | 結尾交換 | 結束候選，未證實所有副作用 |

## 測試順序

1. 先確認測試當下的 5107／510e UUID 與 Android 0x0013／0x0010 handle 對應。不能只依列表順序硬寫。
2. 確認官方 App 身分資訊的生命週期與是否存在配對狀態要求。私人識別字串不植入程式，不把使用者 profile 作為通用測試命令。
3. 在可明確界定命令與副作用後，才建立「實驗連線測試」按鈕：每次只有一個待回覆命令，校验回覆，逾時停止，不盲目重試，不預設修改 profile。
4. 第一個實機目標是穩定取得型號／確認回覆，尚非一次啟動整套測量。記錄命令、回覆及錯誤，避免再次讓使用者逐項試按。
5. 其後才做一次測量與官方畫面对照；Guest 相容性獨立驗證。

## 停止條件

Authentication failed、連線狀態衝突、未知回覆、checksum 不符、逾時即停止。未完成上述證據前不推出「自動測量」按鈕，RD545Adapter 保持明確未驗證錯誤。

## 自動化探索範圍

可離線枚舉大小端、位移、比例、訊息長度與校驗算法，必須用不同資料交叉驗證。不可把數值偶然相同當作欄位證據。此輪不對實體設備暴力發送未知 opcode，因其可能更動或清除個人資料。

目前使用者無須再測量。下一輪先解決 UUID 對應與身分協商，再提供有明確成功／失敗判斷的一次性測試。

## 2026-10-08 靜態核對更新與準備好的測試

從使用者 USB 手機讀取已安裝 Health Planet APK，僅在專案外私人資料夾分析，未修改 App 或讀取登入資料。官方程式的 Android pattern B 明確選擇 5107 TX / 510e RX；診斷記錄亦記錄啟用 510e。常數定義確認 0003 為 VERIFY_UUID、0010 為 WRITE_DATE、0020 為 RETRIEVE_DEVICE_INFO、1002 為 EXCHANGE_USER_INFO、2010 為 MEASURE、3000 為 RETRIEVE_MEASUREMENT_COUNT、3010 為 RETRIEVE_MEASUREMENT_INFO。

新增頁首「實驗：驗證身分與讀取型號」：手動匯入私人 identity-probe.json，僅留記憶體，使用已觀察到的既有 App UUID 驗證（不猜測、不建立或保存新 UUID），然後嘗試讀取型號。刻意省略官方流程的時間寫入與 profile 交換，故設備是否接受這個簡化流程仍待測。命令編碼器僅允許 0003 / 0020，驗證逾時、錯誤回覆與斷線皆停止，不自動重試。

實機成功條件：頁面顯示身分驗證與 RD-545AS 型號讀取成功。失敗則收集錯誤及匯出封包分析，不切換到亂送指令或覆寫配對。這一步不要求使用者測量，正式 Adapter 仍未啟用。
