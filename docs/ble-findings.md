# RD-545AS BLE 離線研究紀錄

狀態：實驗性觀察，不代表正式 Adapter 已可使用。2026-10-08。

## 已有證據

- 使用者提供的 nRF Connect 畫面：TNT_PAIR 提供服務 `273e5100-6b90-4779-83b8-b8bf1dadac35`，通知特徵 510d／510e／510f，無回應寫入特徵 5107／5108。
- 私人 HCI 檔的連線事件對應到同一設備地址；設備回傳包含 `RD-545AS` 型號文字。地址與原始封包不收進專案。
- 擷取到該連線的 35 筆 ATT 封包，涵蓋約 1.5 秒；其中資料封包重組為 13 個訊息。
- 觀察到通知設定 attribute handle 0x0011、TX 0x0013、RX 0x0010。此次未記錄設備服務探索，不能把這些 handle 直接認定為特定 UUID。

## 單一擷取中一致的格式假說

排除 ATT opcode 與 attribute handle 後，資料前 4 bytes 為候選格式：前兩 bytes 為 big-endian 分段位移（每段增加 16）、最後一段索引、此段有效長度。第二次擷取跨越位移 255，已推翻第一個 byte 固定保留為 0 的早期假說。每段最多 16 bytes，通知尾端可能有補零，須依有效長度截取。

重組後：前兩個 bytes 以 big-endian 表示剩餘長度；全部 bytes 加總取低 8 bits 為 0xFF。13/13 訊息符合這兩個條件。這只證明與現有樣本一致，尚未證實所有模式都使用相同格式。

候選訊息代碼的對應：0003→8003、0010→8010、0020→8020、1000→9000（兩次）、1002→9002；最後有 2010，擷取內無對應回覆。8020 含型號字串。其餘用途不以代碼自行命名為已驗證指令。

## 還不能下的結論

- 未確認體重、體脂、肌肉量及分部位指標的欄位位置、單位與比例。
- 不能斷言此記錄包含完整測量流程；可辨識的內容偏向設備資訊與個人設定交換。
- 不能從此次擷取斷言 510f 是必要測量通道，或訂閱失敗是零封包的主因。
- 不可重播帶有 App 識別與個人設定的 TX；可能更動設備內容。
- 不支持 Guest BLE 或正式自動測量的宣稱。

## 工具

`tools/analyze-tanita-att.mjs` 為離線分析器，只接受已篩選的 ATT JSON，輸出重組結果。工具不連線、不送出指令、不產生健康數值。輸入與輸出都必須放在專案外的私人目錄。輸出含原始資料，不可提交到 GitHub。

## 下一份證據的需求

需要覆蓋「App 開始測量→人站上設備→App 顯示此次新結果」整段通訊，並以少量本次顯示值與時間作比對。不要在測量尚未完成時開始診斷打包；先確認記錄已啟用，再完成測量，再匯出。既有樣本不足以直接實作測量解碼。

## 第二次擷取更新

上述「未辨識測量結果」為第一份擷取的結論。第二份已涵蓋完整等待結果的交換：2010 送出後約 64 秒收到 a010，接著 3000→b000、3010→b010，最後 0001→8001。這些用途仍為時序推論，未經主動命令測試。

b010 為 346 bytes、22 段；重組後長度與加總校驗符合規律。5 個候選欄位與使用者提供的同次官方 App 截圖相符：6021 體重（uint16 BE /100）、6022 體脂率（uint16 BE /10）、6023 肌肉量（uint16 BE /100）、6025 內臟脂肪（uint16 BE /10）、605b 肌肉品質（uint8）。真實值與原始資料僅存專案外私人目錄。

這是單樣本的欄位候選對照，不是完整欄位 parser：不可在任意資料中單靠搜尋 tag 就認定找到欄位，因相同 bytes 可能存在於數值內。還需要欄位邊界、不同數值樣本與單位變化驗證。正式 RD545Adapter 仍維持未驗證錯誤，未新增任何可執行 BLE 命令。

已使用全合成資料驗證 22 段／超過 255 的位移能完整還原。抽取器用 HCI 連線事件篩選目標設備，支援 ACL continuation；不把其他藍牙設備流量混入結果。
